# POS online without disrupting LAN

Public address: **https://cccpos.dpdns.org**. This deployment publishes POS only.
ERP containers, database, port 80, URLs, host firewall, and DNS settings are preserved.

## Independent LAN and public runtimes

- LAN: existing `app` → existing PostgreSQL. Existing addresses remain
  `http://192.168.0.46:8081` and `http://192.168.1.46:8081`.
- Public: Cloudflare HTTPS → `tunnel` → `online-proxy:8080` → `online-app:3000`
  → the same PostgreSQL database.
- The three new services publish **no host ports**. No router forwarding,
  cashier certificate installation, hosts-file edits, or local DNS changes are needed.
- `online-app` uses the same image as the working LAN application. It has separate
  HTTPS origin and Secure cookies. Existing LAN origin/cookie settings remain unchanged.
- Accounts, products, transactions, sessions, permissions, rate limits, and backups
  share the existing database. There is no data copy, synchronization job, or second ledger.
- Stopping the tunnel, an internet outage, or a Cloudflare outage does not stop
  LAN POS. A server, Docker, LAN, or database outage affects local operation.
- Online services have CPU and memory limits to constrain additional host load.
  Both runtimes still share server/database capacity; verify capacity before major events.

## Configuration and activation

Keep the `ccida-pos` project name and its existing PostgreSQL 17 and backup volumes.
Do not enable the old `standalone-https` profile: it claims ERP's port 80.

Private configuration is ignored by Git and Docker image builds:

- `deploy/.env.pos-online`: copy of production LAN configuration, plus `POS_HOSTNAME`
  and an absolute `CLOUDFLARE_TUNNEL_TOKEN_FILE` path.
- `.local/secrets/cloudflare-tunnel-token`: mounted connector secret.
- `.local/secrets/cloudflare-storage.json`: API provisioning credentials.
- `.local/secrets/r2-backup.json` and `restic-password`: encrypted backup access.

Protect these using NTFS ACLs. Do not print tokens or environment dumps. Rotate
credentials previously disclosed in chat and update the protected files accordingly.
Keep an independent secure copy of the restic password for disaster recovery.

```powershell
powershell -ExecutionPolicy Bypass -File deploy/cloudflare-pos.ps1
# Only for first-time configuration; refuses to overwrite an existing file:
powershell -ExecutionPolicy Bypass -File deploy/prepare-online.ps1
node tests/online-deployment.mjs
powershell -ExecutionPolicy Bypass -File tests/deployment-update.ps1
powershell -ExecutionPolicy Bypass -File deploy/activate-online.ps1
node scripts/online-smoke.mjs
```

The remotely managed tunnel is `ccida-pos-production`. Its only published hostname
is `cccpos.dpdns.org`, routed to `http://online-proxy:8080`. Allow outbound tunnel
connectivity on TCP/UDP 7844 plus ordinary DNS/HTTPS. No inbound host/router changes.

Activation acquires the deployment lock, records LAN/ERP/database identities and
business totals, and verifies a pre-activation database dump. It tags the running
LAN image as `ccida-pos-online-app:current`, then starts **only** `online-app`,
`online-proxy`, and `tunnel`. It verifies tunnel connectivity and confirms LAN,
database, and ERP container identities were preserved before publishing DNS.
Business totals are recorded without creating test sales or modifying operational records.

Cloudflare provisioning creates only the exact POS tunnel CNAME, scoped cache-bypass
and HTTP-to-HTTPS rules. Existing conflicting DNS records cause an error rather
than being overwritten. Other DNS/rules are preserved. The proxy also sends
`Cache-Control: no-store`, permits 20 MiB product uploads, rejects other hostnames,
and overwrites client-IP headers from Cloudflare's trusted tunnel path.

Staff use existing login/role permissions. Public `/feedback` remains available;
do not place a site-wide Access login in front of customer links. QR links generated
by the public runtime use the public origin. Links generated by the unchanged LAN
runtime may retain the LAN origin; use the public runtime when distributing links
to external customers.

## Operation and backups

Check LAN health, public health, worker status, tunnel readiness, disk space and
backup freshness. Tunnel readiness is `http://tunnel:2000/ready` inside the tunnel
network. A running connector is not sufficient evidence that it is connected.

The original backup worker remains the only scheduling worker. Set its existing
Super Admin backup schedule to 1 hour. To commission it through audited APIs, set
`POS_ACCOUNTS_FILE` to a protected JSON file of current authorized account credentials
(`username`, `password`, `roleName`). Without that file, the smoke script checks health,
public feedback and origin/authentication guards without attempting passwords.
Do not rely on old commissioning passwords or reset existing passwords for deployment.

```powershell
node scripts/online-smoke.mjs --enable-backups
powershell -ExecutionPolicy Bypass -File deploy/run-offsite-backup.ps1
powershell -ExecutionPolicy Bypass -File deploy/schedule-offsite-backup.ps1
```

Offsite snapshots use restic encryption within the dedicated R2 prefix
`cida-pos-private/ccida-pos-online`. The script includes a verified fresh database
dump, registered backup archives, and private environment configuration. Retention
keeps 30 days for this application's host; it never deletes operational archives.
An initial encrypted commissioning snapshot was also created before activation.

The Windows task runs at 02:30 local time and at user logon, with retry on failure.
It uses the Docker Desktop user's interactive account; Docker Desktop must be
running. Check task results after reboot. Do not assume unattended availability
without testing startup on the actual Windows host. This setup does not reboot the
PC or change shared Windows/Docker power settings while ERP is operating.

Periodically restore a selected encrypted snapshot to a protected separate directory,
verify SHA-256, and rehearse restoration into an isolated empty PostgreSQL 17 instance:

```powershell
powershell -ExecutionPolicy Bypass -File deploy/verify-online-backup.ps1 -Archive PATH_TO_DUMP -ExpectedSha256 VERIFIED_HASH
```

The drill container publishes no ports and uses its own temporary database. Never
restore over live financial records; follow `docs/backup-restore.md` for recovery.

## Updates, rollback and acceptance

After source publication and passing GitHub validation:

```powershell
powershell -ExecutionPolicy Bypass -File deploy/update.ps1 -Online -WhatIf
powershell -ExecutionPolicy Bypass -File deploy/update.ps1 -Online
```

The updater builds matching LAN/public images, verifies a pre-update backup and
migrations, updates POS runtimes and checks local health plus connected-tunnel
readiness. It preserves the LAN settings copied into the online environment.
A plain LAN update is rejected while the online proxy is active, to prevent the
public runtime from silently remaining on an older release. Normal application
updates may briefly restart POS web services; tunnel activation itself does not.

To remove public access without affecting LAN:

```powershell
docker compose -p ccida-pos --env-file deploy/.env.pos-online -f compose.yaml -f compose.online.yaml stop tunnel online-proxy online-app
```

Optionally disable the exact POS DNS route in Cloudflare. No LAN environment,
hosts-file, certificate, database, or application rollback is necessary. Never use
`down --volumes`, database reset, or an old database restore for tunnel rollback.

Acceptance: verify all five roles and wrong-origin rejection on both LAN addresses
and public HTTPS; public feedback; shared catalog reads; unchanged financial totals;
ERP identity/access; and LAN login with the tunnel stopped. Physical printer/scanner,
a second LAN device, mobile-data and reboot tests require those devices/an operator.
